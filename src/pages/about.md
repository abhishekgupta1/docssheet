# About docssheet

**docssheet** is a free reference site for people who build and run software:
software development engineers in test (SDET), site reliability engineers (SRE),
backend engineers, and engineers moving into technical leadership.

It has two halves that are meant to be used together:

- **Docs** — longer guides that build the mental model for a topic: what it is,
  why it works the way it does, worked examples, common mistakes, and how it
  shows up in interviews and on the job.
- **Cheat sheets** — one-page, scannable versions of the same topics for when
  you already understand the idea and just need the syntax, the flag, or the
  command.

Around those sit a few **learning tools** — a skill roadmap, a proficiency
matrix, a spaced-repetition quiz, and a progress dashboard — that help you work
through the material in an order that makes sense and keep track of what you've
covered. Your progress is stored only in your own browser; there are no accounts.

## How the content is made

Every guide is written from hands-on use of the tool or practice it describes,
then structured against a fixed template so the site stays consistent as it
grows:

1. a short "mental model" diagram and a 10-minute path through the essentials;
2. a build-up from first principles with runnable examples;
3. failure modes and the mistakes people actually make;
4. interview questions and exercises;
5. a cheat sheet that mirrors the guide for fast lookup.

Third-party names, trademarks, and documentation are referenced only for
identification and educational commentary. Where a page leans on an external
source, it links to it rather than reproducing it. Code samples are
illustrations — test and adapt them before using them anywhere that matters
(see the [Disclaimer](/disclaimer)).
